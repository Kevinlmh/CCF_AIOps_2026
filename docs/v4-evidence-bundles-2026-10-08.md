# v4 第四阶段交付：审阅关联、证据包和查询

## 设计回顾

[架构一致性检查](v4-design-audit-2026-10-08.md)确认目前代码符合已批准的主线：原始统计 → 显式时间与语义的窗口 → 稳健统计/轻量聚类/规则 → 候选事件。参考按 native series 独立建立，以保留接口、peer、业务目标差异；稀疏参考显式不可用，不是已知正常模型。

本阶段补齐候选到 LLM 的证据接口。LLM 事件确认、独立根因定位与故障分类、复核、官方导出和诊断评测仍未实现。没有读取标签、旧特征库或调用模型；提交脚本未读取或执行。

## 已实现

- `aiops_v4/evidence/association.py`：按同网元严格重叠形成审阅关联；接触边界、时间空缺和不同身份不硬合并。传递关联保留每个原事件，不代表单一故障或故障持续时间。
- `packet.py`：支持、无当前触发的可评分观测、质量上下文及全局/局部缺失说明。保留 native grain、规则事实、统计 drivers、参考/时间覆盖、检索锚点。每包最多32个事件ID、32个原始引用（覆盖全部嵌套观测），各类观测默认8条，可调1..32；关联最多8条，完整数量和截断显式可见。评分来源包含参考模式/区间、触发配置和输入摘要。
- `raw.py`：磁盘排序引用，原始文件每文件一次扫描至最大所需行；验证 record_id、位置及物理行。完整日志、五元组及原始字段保留。`observed_time`按窗口层配置解释；原始时间与数据层暂定 timestamp 同时保留。
- `index.py`：SQLite保存完整状态、矩阵、模型、事件、窗口/事件/包成员关系和全部已登记状态锚点。只物化包内原始引用；其他登记引用按需重新读取并核验。所有查询要求匹配 batch，连接只读，支持分页及带时区的半开重叠范围。
- `pipeline.py` / CLI：核验上游摘要与窗口哈希，从所链接窗口独立生成临时磁盘向量并逐条核对完整矩阵，验证参考范围、ID唯一、连续候选成员及计数；事件引用必须属于自身成员窗口。只发布新目录，summary最后写入，失败回滚自有文件。支持原始目录迁移、跳过物化及可选带来源的拓扑。

目前仓库有官方80网元名单，没有可信拓扑连线文件。适配器要求非空provenance、合法端点且输入边不超过512条；仅关联直接相邻并严格重叠的包，未推断因果方向或路径。两组实测都未提供拓扑，因此 relations=0，明确 unavailable。

精简观测按时间、source、group排序选有界例子；不能据此覆盖所有视角或直接裁定故障。完整线索需通过 `states/members/model/relations` 工具补取。不可评分、没有文件/没有记录均不当作正常反证。

## 测试与实测

实现前观察到8个关联/包、9个原始读取、14个索引/CLI缺失失败，逐阶段通过后提交。生产者驱动测试覆盖跨视角37成员包及分页、规则证据、原始按需读取、多行长日志、显式+08时间、前缀范围、拓扑严格重叠、坏批次/重复/坏成员/数量/摘要链接/矩阵粒度拒绝、输出保护、失败回滚和数据库只读。

一次独立只读审查发现4个Important问题：原事件可借用其他状态锚点、真实另一轮摘要可给旧矩阵错误归源、嵌套引用突破总预算、角色查询缺少参考/阈值信息。7项回归场景观察到失败后完成修正，全套170项测试通过；无Critical或Minor，没有二次审查。版本1实验包含上述缺陷，原样保留但查询拒绝；修正后的包、summary和SQLite使用契约版本2，窗口/状态输入仍为1。

每个原事件恰好进入一个包，每个候选窗口恰好进入一个原事件；最大包分页没有遗漏或重复。所有包的事件ID、引用、观测及关联容量检查通过，包内原始引用全部物化。SQLite integrity/foreign_key检查通过；完整查询、分页和未物化锚点按需核验后数据库SHA256不变。453个既有受保护文件的大小和mtime未改变。

第二批前缀中24,000个routing窗口与290个NetFlow窗口全部为 insufficient_reference；routing有69个规则候选窗口，NetFlow没有候选。不能据此宣称NetFlow正常或全批次无异常；短前缀、原始序列粒度和显式参考范围限制了参考可用性。公开样例NetFlow有5,249个可评分窗口和559个候选，另185个参考不足。后续真实LLM实验必须保留这些可用性边界。

修正后的产物位于 `outputs/v4/evidence-bundles/20261008/public-reviewed/` 和 `stage2-prefix-reviewed/`；逐项核验记录为同级 `verification-reviewed.json`，计时记录为 `*-reviewed-run.json`。运行命令见 [README](../README.md)。性能数字只是这两次本地运行，第二批前缀不是43.2GB全量性能或分布结论。审查前的 `public/`、`stage2-prefix/` 与 `verification.json` 作为实验记录保留，不用于后续角色输入。

## 这一步的结论与下一步

候选与原始记录之间已有可追溯、可分页、显式保留缺失和范围限制的桥梁，可以开始实现 LLM 角色。审阅包数量变化只反映关联压缩，不表示故障数或准确率提升。

下一阶段先完成共享后端、结构化角色输入输出和事件确认角色，接入上述只读工具；用离线后端测试无证据、坏JSON、工具错误及调用预算，再开展真实模型实验。之后独立实现根因定位、32类故障分类和一致性复核，最后接官方导出与评测。首批数据可另做独立验证，当前证据代码不依赖它。

## 实施判断

保留用户指定v4工作区并逐项执行；未另建分支或合并，代价是改变当前工作区。拓扑需要来源，缺失连线保持可见，代价是暂不能提供邻接关联。同网元重叠包作为审阅上下文而非确认故障，故障确认仍需后续角色。全部状态锚点保存在磁盘，以支持精简包外检索，代价是更大的SQLite索引。

拒绝版本1证据契约，代价是旧证据需在新目录重新构建。审查中明确不裁定未来LLM诊断/导出/准确率，代价是诊断结论和评分须等待下一阶段；不从前缀推断第二批全量分布或吞吐，代价是仍需完整数据实验。无待处理Minor问题。
