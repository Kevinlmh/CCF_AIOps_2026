## 复现出的链路问题与修正

原 v3 按单网元形成事件，第一批输出 478 条。其中 89 条由 `routing.bgp_peer_up` 触发；同一 BR 的数分钟 BGP 抖动以及两端同步掉线被反复报告。另有同步的多网元 CPU 异常被各报一条。单纯把全网同分钟异常合并又会吞掉独立故障，因此修正采用三个可审计条件：

1. 同一网元短间隔 BGP 段只在合并后**每个原始段**与合并时间段的 Dice 系数仍至少为官方匹配门槛 0.4 时合并。
2. 不同网元只在直接证据类别相同、起点相差不超过 1 分钟、时间段明显重叠、同一原始指标的曲线相关性达到 0.75，且每个原始段仍满足上述 Dice 条件时合并。
3. 不同故障类别、相邻但未重叠的网元异常、曲线形状不相似的同分钟异常保持独立。合并后保留所有触发证据和合法根因候选，并把原事件 ID 与最终 ID 的关系写进 `run_manifest.json`。

第一批现输出 **375 条**，比原 v3 减少 103 条；运行清单记录 87 次同步同类合并、16 次同网元 BGP 抖动合并。BGP 类候选从原 v3 的 89 条变为 43 条，接近数据侧 v2 的 47 条，但两者都不是准确率证据。相对官方 292 条，预测仍多 83 条；当前没有依据将这 83 条指定为误报。
