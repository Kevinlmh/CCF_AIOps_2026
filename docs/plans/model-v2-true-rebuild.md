# v2.0 模型实施与阶段结论

设计依据：[v2.0 重构设计](../design/model-v2-true-rebuild.md)。本计划保留可复用结论，不逐次记录临时实验文件。

## 当前链路

- 默认直接检测负责事件触发；神经检测仍是显式选择的对照/实验链路。
- 神经模型先产生 node / edge / log 分实体分数，再用训练期拟合的网元级稳健校准器归一化，之后做来源门控与分钟级融合。
- NetFlow 不进入神经事件触发池。Traffic 边只有在请求感知的服务质量证据（错误率、延迟或丢包）通过门控时才可触发；吞吐/流量波动本身不够。node/log 也要求同一网元同一分钟有直接语义支持。门控外分钟仍作为可观测零分参与校准，避免只用候选分钟拟合阈值。
- 原始时间序列、mask 和实体分数仍保留给后续定位，不把校准分数替换成 RCA 输入。
- checkpoint v5 保存网元校准参数；v1–v4 仍可读取，缺少网元校准参数时沿用旧神经评分路径。

## 为什么调整

八城无标签对照中，旧神经链路曾产生 1,672 条候选；高分分钟受极端 node 特征和 NetFlow edge 主导。`asinh` 变换虽降低事件数，却漏掉 13 分钟 CPU、磁盘和内存故障注入；Top-k 又使大量 NetFlow 分数进入高分区。仅增加 epoch 没有证据能解决这个评分结构问题。因此这次先分实体校准，并明确触发源约束；不按预期事件总数截断，不声称无标签候选数等于真故障数。

## 验收状态与边界

- 自动化：完整测试集 173 项通过，另有 3 个 subtests 通过。
- 公开样例和直接检测默认路径：本轮未改变其触发逻辑，完整测试集已通过。
- 八城一轮受控神经预测：1 epoch 训练损失 2.336、时间留出验证损失 2.886；得到 958 条候选，直接检测历史输出为 457 条。高分边分钟现均由 Traffic 边贡献，审计中没有 NetFlow 触发。候选数差异不能说明精度变好或变坏，stage1 没有完整真值用于判断。
- 在八城特征库的一段 480 分钟背景切片做 13 分钟故障注入：无注入有 16 条背景事件；CPU 40%、可用内存比例 0.03、磁盘利用率 95% 注入后分别有 17 条事件，三者都产生与注入区间重叠的事件。CPU 和磁盘事件的峰值概率分别约 0.783、0.646；内存约 0.999。链路能响应受控变化，但低置信度 CPU/磁盘检测仍需分析，注入实验不能代替真实标签评估。
- 现已适合进行“1/3/5 epoch 的受控对照”，不表示神经链路已可替换直接检测或可提升比赛分数。需固定数据切分与推理配置，同时比较验证损失、三类注入召回、背景候选和事件区间稳定性；不按事件数优化。
- 八城无标签审计只能比较评分分布、候选驱动源与时序稳定性，不能替代隐藏标签精度评估。最新可复现实验在忽略目录 `outputs/v2_0/neural_entity_calibration/`。

## 需要保留的实现依赖

`baseline/bian/preprocessing/observations.py` 和 `multisource.py` 仍被 v2 的数据流及测试直接导入，不能作为“旧版冗余”删除。若未来要移除整个 `baseline/`，应先迁移 canonical observation 类型和多源解析器，并完成接口回归；本轮不扩大这个重构范围。
