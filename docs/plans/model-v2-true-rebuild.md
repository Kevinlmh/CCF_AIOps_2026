# v2.0 重构实施计划

设计依据：[model-v2-true-rebuild.md](../design/model-v2-true-rebuild.md)。继续在当前 `main` 工作目录实施，不改写既有提交；每项先写合成测试再改实现。

1. 基线与目录审计：记录 v1.6/v2.0 公开报告，确认可清理文件的引用关系。
2. 输入契约：同时识别官方样例 `processed` 和第一批正式数据 `*_data`，同名副本不得重复读。
3. 直接证据检测：实现带 mask 的 `[T,N,C]` 语义量程、请求量收缩及持续性；traffic/NetFlow/scrape 与本机根因分层。
4. 事件/定位/分类：接全局非重叠解码、Top-5 与候选条件分类；CPU 伴随磁盘/内存故障时优先识别特异性锚点。
5. 入口与后端：默认 `all/predict` 不要求 checkpoint；旧神经检测仅作可选对照；服务器 LLM 复核接口默认关闭。
6. 验收：全体单元测试、从原始公开样例重建评测、成都单城无标签审计；全量八城留给服务器运行，不以事件总数调参。

当前进度：1–6 的代码与单城审计已执行。公开样例 96.01 分；成都七源读取成功，输出 170 个无标签候选，其中约 123 个由服务质量观测主导。修复 NetFlow 列表内存风险后，用同一成都原始目录重建特征：约 381 秒、最大 RSS 754 MB，新旧 manifest 完全相同；临时验证副本已删除。成都探针包含跨城目标，不能把 170 当作成都本地故障数。八城完整预测和隐藏标签准确率尚未验证。

2026-09-24 证据链补强：已从八城原始数据构建的 feature store 完成无 LLM 复跑。FRR 严重事件与有足够流记录数、同一特征连续异常的 NetFlow 构成有上限的定位补充证据；NetFlow 不参与事件触发，定位时只计入相对事件前的增量，且贡献受直接证据/FRR 上限约束。新增独立审计命令记录事件峰值驱动源、Top1 直接/FRR/NetFlow 证据及类别锚点状态，区分 NetFlow 原始峰值与实际排序贡献，不修改提交 JSONL。对同一八城 store，事件区间仍为 457/457 一致；Top1 变化 19 条，类别变化 18 条。磁盘类别缺少 Top1 直接锚点的事件从 195 降到 186，但峰值驱动节点与 Top1 不同城的事件从 9 升到 13，说明跨城排序仍需在数据侧核对拓扑与故障传播后才能判断好坏；不能据此声称隐藏集精度提高。公开三样例回归仍为 96.011111 分，TP=3、FP=0、FN=0。验收输出为忽略的 `outputs/v2_0/evidence_chain_audit_20260924/verified_*`，代码测试为 147 passed、3 subtests passed。下一轮应优先核查 186 条无根因直接锚点的磁盘判定和跨城传播证据，而不是按官方故障总数裁剪事件。

2026-09-24 至 09-25 根因—类别一致性优化：以同一八城 feature store 复跑，不重新解析 CSV。磁盘利用率的语义证据按 0–100 量程连续衰减，读写速率留作直接检测弱辅助，不单独生成磁盘类别；候选根因先验投票乘绝对语义强度，避免极弱信号被归一化为完整类别票。目标城市和观测端的多条业务边均按最强边计分，避免边数重复加票。吞吐下降不再单独映射为限速类别，无语义证据时合法默认类别的内部置信度为零。最终 `reviewed_stage1_*` 仍有 457 条、时间区间 457/457 相同、无重叠且时长 1–30 分钟；Top1 变化 53 条、类别变化 220 条。磁盘类别无 Top1 直接锚点由 186 降至 1，跨城峰值驱动与 Top1 不同城由 13 降至 11；公开样例仍为 96.011111 分，TP=3、FP=0、FN=0。必须保留的风险是 `link.delay` 升至 40 条，其中部分 Top1 没有对应语义信号；无完整真值不能断言类别迁移提高真实得分。验收输出在忽略的 `outputs/v2_0/causal_consistency_20260924/reviewed_*`，下一轮应结合数据侧解释服务延迟、链路时延与目标设备的因果关系，避免继续无标签硬调。
