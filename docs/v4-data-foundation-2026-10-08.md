# v4 第一步：原始数据基础交付

本次完成读取、统计、质量检查和证据查询。总体方案为：统计特征与轻量聚类发现运行状态，规则补充异常线索，同一个 LLM 通过多个角色完成事件确认、根因定位和故障分类。后面的算法层尚未实现。

## 已实现

- `aiops_v4/data/discovery.py`：七类 CSV 自动发现，列出所有识别文件，支持嵌套批次目录。
- `contracts.py`、`reader.py`：保留原始字段的记录协议和流式读取；包含完整日志、接口、peer、流量端点、原始时间、批次、稳定 ID、文件及物理行号。坏值/未知网元不删除，打质量标记。
- `statistics.py`、`profile.py`：字段词典、来源/网元/时间覆盖、缺失/零值/坏值计数、数值矩和有界分位数、有限窗口重复和乱序线索。routing 按 metric_name 分开，指标按角色另行统计。
- `store.py`：可选 SQLite 原始证据快照；完整记录和扫描范围一起保存，失败不发布部分数据库；只读、批次限定查询。
- `cli.py`：`profile`、`ingest`、`query`；输出机器可读 JSON、字段 CSV 和 Markdown 报告。拒绝覆盖已有结果，输出须在输入目录外。

新数据层只借用通用代码的目录城市识别和官方配置，不继承旧差分、NetFlow 聚合或日志摘要。旧特征库没有作为 v4 的默认输入。

## 数据结论与后续约束

1. 两种本地目录结构均能直接读取；不需要整体重写旧通用解析器，新增原始层已提供后续输入。
2. 所有已扫描记录的原始时间均不带时区，统一标记 `assumed_utc`。报告中的 UTC 是暂定解析结果，必须核验后才能计算事件时间和评分。
3. 公开样例发现 80 个允许提交的网元。另有 1,104 条 `probe-vm` 观测未映射到官方候选网元：node 184、interface 736、scrape 184。保留这些辅助观测，不能强行转换成允许提交的根因网元。
4. 公开样例 FRR 的 8 个文件均为空；第二批本地目录发现 node/interface/routing/scrape/netflow 五类，没有 traffic/FRR 文件。缺少这两种模态不能当成正常证据，也不能据此断言官方完整数据不含它们。
5. NetFlow 基数高，公开样例时序跟踪发生 521,704 次淘汰，第二批前缀发生 28,161 次；因此间隔/乱序检查只能提供有限跟踪线索。公开样例观测到 194 次时间倒序，没有删行或按此判故障。字段和指标分组均未触及上限。
6. 原始层不填零、不差分计数器、不推断异常方向。分位数和 MAD 是蓄水池估计，字段名只能提供计数器线索，不能替代语义核验。

这些结果证明数据接口能运行和追溯原始证据，不能证明聚类可分故障或 LLM 诊断准确率。

## 剩余编码工作与下一任务

下一步实现**多视角窗口特征与轻量聚类的最小闭环**：

1. 核验时间语义、字段单位和计数器含义，建立字段语义登记表；把辅助网元与可提交候选网元分开表示。
2. 从新原始层生成设备资源、接口链路、路由 peer、流量路径四类窗口特征，保留计数、缺失率、有效点数和原始证据引用。计数器重置与差分只在此层处理。
3. 每批、每角色/视角独立建立参考尺度；避免把无数据、真实零值和不同设备角色混在一起。先比较稳健统计距离与轻量聚类，不预先把两簇解释成正常/故障。
4. 用状态变化、统计偏离和少量有来源的规则形成候选事件；输出事件证据包和反证，不在这一步声称根因已确定。
5. 用公开样例检查事件覆盖、时间边界和误报，再对第二批全量扫描/离线聚合。旧缓存仅在核验生成逻辑后选择性复用。

其后：共享 LLM 客户端与预算控制 → 事件确认、根因定位、故障分类三个角色及结构化输出 → 一致性复核、事件整理、官方 JSONL 校验/导出 → 消融、成本与耗时统计、容器复现。模型提示词以证据包为输入，缺失证据和规则命中必须显式呈现。
