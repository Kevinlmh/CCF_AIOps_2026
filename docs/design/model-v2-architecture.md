# CCF AIOps 2026 模型 v2.0 设计

## 1. 设计结论

v2.0 不再沿用 v1.x 的“逐序列阈值检测 → 按城市聚合事件 → 规则排序”作为主链路，而采用：

```text
七源 CSV
  ↓ 流式解析、分钟对齐、实体映射
多源分钟级特征存储
  ↓ 按窗口组装张量
自监督多源时序模型
  ↓
全网每分钟故障概率 + 实体异常分数
  ↓
全局半马尔可夫事件解码
  ↓
事件因果子图
  ↓
图模型根因 Top5 + 故障分类
  ↓
可选 LLM 受约束复核
  ↓
predictions.jsonl
```

核心选择如下：

1. **模型输入张量化。** 原始 CSV 仍然分块读取，不把约 2 亿行数据一次性载入内存；读取后先聚合为分钟级特征，再按窗口形成张量。
2. **全网只建立一条事件时间线。** 城市是实体属性，不再是事件切分边界，避免同一个目标故障被八个观测城市重复报告。
3. **流量和 NetFlow 是有方向的边观测。** `source_region → target_region/target_domain`，不能默认把源端 `traffic-vm` 当作根因。
4. **检测主体是可训练的自监督模型。** 规则只负责单位、计数器、状态语义、合法范围和输出约束，不代替模型决策。
5. **LLM 不负责扫描原始数据。** LLM 只读取压缩后的事件摘要，辅助事件复核、根因重排和分类；事件边界仍由时序模型决定。
6. **不以 292 为输出数量目标。** 292 只用于全量结果的事后合理性检查，不能写入解码器或阈值。

## 2. 设计依据

### 2.1 任务约束

- 输入包含节点、接口、路由、采集健康、业务流、NetFlow 和 FRR Syslog 七类数据。
- 第一批数据连续 14 天，官方说明包含 292 个故障。
- 单次故障持续 1～30 分钟，故障通常相隔 20 分钟以上，同一时刻没有并发故障。
- 预测事件未匹配真实故障时，该事件对应的 RCA 和分类均无法得分。
- 根因必须输出合法且不重复的 Top5；分类必须来自官方闭集枚举。
- 不提供训练集，禁止人工标注测试数据、泄漏标签和硬编码测试答案。

### 2.2 v1.x 暴露出的结构性问题

v1.6 全量运行得到 723 个事件，其中 504 个由 traffic 驱动，512 个事件把 `traffic-vm` 排在根因第一位。问题不是继续调整几个阈值就能解决，而是表示与事件切分方式不正确：

- 同一目标服务异常会同时被多个源城市观测到，按城市切分必然重复计数。
- `traffic-vm` 多数是探针或观察者，而不是目标服务故障的根因。
- 逐指标 MAD 分数难以区分业务周期、瞬时抖动、持续故障和恢复尾部。
- 大量证据点先被阈值制造，再通过更多规则筛选，误差会在检测、聚合、定位间逐级放大。
- 仅看局部异常强度，无法学习“多源同时变化”和“根因先于症状”的模式。

因此 v2.0 保留可靠的解析与官方协议代码，但替换检测、事件切分、定位和分类主链路。

## 3. 输入和输出契约

### 3.1 原始输入

输入仍是目录中的 CSV 文件：

| 数据源 | 原始文件 | v2.0 表示 |
|---|---|---|
| 节点指标 | `node_metrics_*.csv` | 节点特征 |
| 接口指标 | `interface_metrics_*.csv` | 节点/物理链路特征 |
| 路由指标 | `routing_metrics_*.csv` | 节点状态与路由关系特征 |
| 采集健康 | `scrape_health_*.csv` | 数据质量特征 |
| 业务流 | `traffic_flow_metrics.csv` | 有向业务边特征 |
| NetFlow | `netflow_5tuple_minute_readable.csv` | 有向通信边特征 |
| FRR 日志 | `frr_syslog_events_*.csv` | 节点离散事件特征 |

v2.0 不要求 CSV 天然具有统一列结构。每类解析器负责把原始字段转成稳定的分钟、实体、指标和值。

### 3.2 实体索引

建立三个稳定索引：

```text
node_index    官方可提交网元 ID → [0, N)
edge_index    有向通信/拓扑边     → [0, E)
feature_index 规范化特征名         → [0, F)
```

第一批公开枚举包含 8 个城市、每城 10 类网元，因此官方候选节点数 `N = 80`。内部允许使用“某城市某服务组”等虚拟聚合节点，但虚拟节点不能直接进入提交结果，必须映射回官方候选。

当前公开 `network_elements.json` 只有城市和设备角色，没有物理链路拓扑；首版边索引只来自数据中实际出现的 traffic 与 NetFlow 关系，不虚构设备连接。边集合在特征构建开始时扫描确定，随后保持索引稳定。

### 3.3 模型张量

训练和推理的一个批次采用以下张量：

```text
node_x       [B, T, N, F_node]   节点、接口、路由和采集特征
node_mask    [B, T, N, F_node]   真实观测掩码
edge_x       [B, T, E, F_edge]   traffic 与 NetFlow 特征
edge_mask    [B, T, E, F_edge]   边观测掩码
log_x        [B, T, N, F_log]    日志模板计数、严重度和状态变化
log_mask     [B, T, N, F_log]    日志可观测性掩码
time_x       [B, T, F_time]      分钟、小时、星期等周期特征
graph_links  [2, L]              有向观测边到目标网元的消息索引
```

- `B`：窗口批次数；
- `T`：上下文长度，默认 120 分钟；
- `N`：候选节点数；
- `E`：观测到的有向边数；
- `F_*`：各模态特征数，由特征注册表固定。

缺失值不能直接解释为零。数值数组中可临时使用零作为存储占位，但模型始终同时接收 `mask`，损失函数只在真实观测位置计算。

### 3.4 中间输出

模型中间输出：

```text
node_anomaly        [B, T, N]    每个网元的异常分数
edge_anomaly        [B, T, E]    每条边的异常分数
log_anomaly         [B, T, N]    每个网元的日志异常分数
family_anomaly      [B, T, 3]    节点、边、日志分支分数
fault_probability   [B, T]       兼容字段；实际为未校准分支合成分，只用于调试
node_embedding      [B, T, N, D] 网元时序表示
edge_embedding      [B, T, E, D] 边时序表示
```

`fault_probability` 仅为兼容和调试字段，实际未经校准，不得作为最终预测概率使用。外部稳健校准器将 `family_anomaly` 转为全网每分钟概率 `[T]`，再交给全局事件解码器；未训练的神经网络分类头不参与预测。

### 3.5 最终输出

最终仍使用官方 JSONL，一行对应一个全局事件：

```json
{
  "prediction_id": "pred_000001",
  "start_time": "2026-08-19T07:01:00.000Z",
  "end_time": "2026-08-19T07:10:00.000Z",
  "root_cause_top5": [
    {"rank": 1, "network_element_id": "wuhan-service-vm-1"},
    {"rank": 2, "network_element_id": "wuhan-service-vm-2"},
    {"rank": 3, "network_element_id": "wuhan-fw"},
    {"rank": 4, "network_element_id": "wuhan-br-1"},
    {"rank": 5, "network_element_id": "wuhan-br-2"}
  ],
  "fault_category": {
    "major_category": "service",
    "sub_category": "auth_error"
  }
}
```

## 4. 数据预处理与特征存储

### 4.1 两阶段处理

```text
阶段 A：CSV → 分钟级特征存储
阶段 B：分钟级特征存储 → 训练/推理窗口张量
```

阶段 A 仍采用流式、分块读取，可按城市和数据源并行。阶段 B 使用内存映射或分块数组按需读取，避免反复扫描约 96 GB 原始数据。

建议目录：

```text
data/feature_store/v2/
├── manifest.json
├── entity_index.json
├── feature_registry.json
├── topology.json
├── node/
├── edge/
├── log/
└── quality/
```

首版优先使用 NumPy 内存映射分片，减少额外依赖；接口保持独立，后续可切换为 Zarr 或 Parquet。

### 4.2 时间对齐

- 所有时间统一为 UTC 分钟。
- 同一分钟同一实体同一特征存在多条记录时，按照特征语义选择 `last/max/sum/mean`，不能统一求和。
- Counter 先识别复位，再计算非负分钟增量。
- Gauge 保留最后值、均值、最大值和变化量中的必要组合。
- 状态量保留当前状态、状态变化次数和距离最近变化的时间。
- 同时保留 `observed`、`missing`、`stale`、`counter_reset` 等质量标记。

### 4.3 多尺度特征

原始分钟特征之外，预处理层只生成不依赖标签的通用特征：

- 一阶差分和相对变化；
- 3、5、15、30 分钟滚动统计；
- 同小时/星期周期基线偏差；
- 有界指标的量程位置；
- ratio 的分子、分母和贝叶斯收缩值；
- 同目标服务的跨源城市一致性；
- 同一拓扑邻域的同步变化；
- 日志模板计数与严重度分布。

规则仅负责生成这些输入特征，不直接判定事件。

### 4.4 数据泄漏控制

- 标准化器只使用数值本身，不读取 `ground_truth.jsonl`。
- 使用中位数/IQR 等稳健统计量，并对极端值截断。
- 自监督训练先使用全部无标签窗口，再依据第一轮重构误差剔除最高异常分位后重训一次，降低故障窗口污染。
- 公开三个样例用于回归验收和结构检查，不作为唯一调参目标。

## 5. 自监督多源时序模型

### 5.1 编码器

采用三条轻量时序分支，而不是让一个大 Transformer 直接接收所有原始字段：

1. **节点分支**：节点资源、接口、路由与采集质量；
2. **有向边分支**：traffic 的请求量、成功/错误/超时、延迟和吞吐，以及 NetFlow 的包、字节、连接和协议特征；边关系和特征名保留数据源语义；
3. **日志分支**：FRR 模板计数、严重度和状态变迁特征。

每条分支由特征投影、缺失掩码编码和因果 TCN 组成。TCN 用于学习 1～30 分钟局部变化，同时以 120 分钟上下文建模故障前基线和恢复过程。

### 5.2 跨源融合

首版分支表示采用日志门控和观测边到目标节点的消息传递：

```text
同一网元：门控融合 FRR 日志与节点表示
实体之间：将 traffic 边表示聚合到目标服务网元
```

当前代码按 traffic 的目标城市映射服务组；NetFlow 仅作为源网元接口证据。公开配置没有物理拓扑，因此首版不声称完成完整物理拓扑消息传递。采集健康当前作为节点输入特征，尚未实现对其他模态缺失值的显式可信度门控；`scrape_up=0` 不能单独决定根因。

### 5.3 训练目标

无标签训练使用以下联合损失：

```text
L = λ1 L_masked_reconstruction
  + λ2 L_next_step_forecast
  + λ3 L_cross_source_consistency
  + λ4 L_topology_consistency
```

- `L_masked_reconstruction`：随机遮蔽真实观测，让模型恢复被遮蔽值；
- `L_next_step_forecast`：预测后续若干分钟，学习正常变化规律；
- `L_cross_source_consistency`：同一故障链相关模态应有一致表示；
- `L_topology_consistency`：相邻节点和边的变化应符合拓扑方向。

异常分数来自幅度、遮蔽重构误差和因果预测误差；训练还含同网元日志/节点表示一致性与观测边/目标节点表示一致性。当前尚未实现独立的表示距离项或合成扰动训练。模型学习正常行为，故障是对正常模式的持续偏离。

全局概率由独立校准器从无标签时间线生成，不使用没有监督目标的随机故障分类头。标定先以边界片段估计初始中心，再取跨源异常能量较低的 60% 时间点拟合稳健分布；这是稀疏故障假设，仍需全量审计验证，不能视为已证明的正常段。

### 5.4 合成扰动

为了训练根因和分类头，可以在低异常的正常窗口上生成通用、可审计的合成扰动，例如：

- 持续 CPU、内存、磁盘或进程压力；
- BGP/OSPF 状态变化和路由震荡；
- 链路延迟、丢包和限速；
- DNS、Web、Auth 的错误、超时和慢响应；
- 从根因节点沿拓扑传播的延迟症状。

合成器只依据字段语义、公开拓扑和公开故障分类，不读取正式数据标签，也不包含具体时间或 Case ID。合成样本用于预训练，不能替代无标签真实数据上的校准。

## 6. 全局故障检测与事件切分

### 6.1 全局分钟概率

模型先输出各节点、边和因果族异常分数，再通过 Top-K 注意力池化形成唯一的全网分钟概率：

```text
p_fault(t) = Pool(node_anomaly(t), edge_anomaly(t), family_anomaly(t))
```

Top-K 池化避免大量正常实体稀释少数强异常，也避免单个噪声点完全决定全网状态。

### 6.2 半马尔可夫解码

事件切分不再逐城市进行。解码器在整条全网时间轴上选择互不重叠的区间：

```text
NORMAL → FAULT(1～30 分钟) → RECOVERY → NORMAL
```

区间得分综合：

- 区间内故障概率；
- 起点前后的变化点强度；
- 区间内跨源一致性；
- 恢复后的回落程度；
- 事件长度先验；
- 相邻事件间隔的软惩罚。

用动态规划求全局最优非重叠区间集合。1～30 分钟是硬约束；20 分钟间隔是软先验，不能因此删除数据充分支持的相邻事件。

### 6.3 边界确定

- 起点优先取第一条持续性直接证据或全网概率变化点；
- 终点优先取直接证据恢复和故障概率回落位置；
- 业务症状的传播延迟和恢复尾部可以进入事件上下文，但不能无限扩展提交边界；
- LLM 不直接改写边界，只能给出复核建议并记录日志。

## 7. 事件因果子图与根因定位

### 7.1 事件上下文

首版事件子图提取四个时间阶段：

```text
故障前参考：start - 10 分钟 ～ start
故障早期：  start ～ 故障区间前 1/3
故障持续：  start ～ end
恢复窗口：  end ～ end + 15 分钟
```

以事件涉及的节点、拓扑边、业务边和日志边构建小型因果子图。事件摘要保留异常开始时间、峰值、持续性、恢复情况和数据质量。

### 7.2 根因特征

每个官方候选网元形成以下模型输入：

- 本机直接异常强度；
- 异常出现的时间领先程度；
- 故障区间内持续性；
- 故障结束后的恢复一致性；
- 能解释的下游节点和边数量；
- 目标侧业务异常与来源城市的一致性；
- 路由/FRR 状态变化；
- 仅有观察者证据时的负证据；
- 数据缺失和采集异常造成的不确定性。

后续若建立无泄漏的合成训练流程，图排序头可输出：

```text
root_logits [K_event, N]
```

排序时只允许官方 80 个网元进入结果。Top5 必须唯一且通过官方 schema 校验。

### 7.3 traffic 根因约束

- traffic 记录首先归到“源 → 目标服务”的有向边；
- 多个源城市同时指向同一目标异常时，应增强目标侧候选，而不是生成多个源城市事件；
- `traffic-vm` 只有同时出现本机资源、进程、采集或接口直接异常时，才具有较高根因概率；
- 目标域名只能可靠映射到服务组时，先保留服务组表示，再结合目标城市本机证据区分 `service-vm-1/2/3`；禁止仅凭域名字典臆测精确编号。

## 8. 故障分类

目标分类头的设计输入为：

```text
事件表示 + Top5 根因表示 + 因果族分数 + 时序形态 + 拓扑传播特征
```

输出：

```text
category_logits [K_event, C]
```

`C` 来自 `fault_taxonomy.json`，不能在代码中复制另一份不一致的类别表。分类分为两级：

1. 预测大类：link、firewall、resource、routing、service；
2. 在大类掩码内预测合法子类。

训练信号来自合成扰动和通用故障语义。没有足够监督数据时保留原型相似度作为辅助特征，而不是让原型规则直接决定类别。

## 9. LLM 的职责边界

### 9.1 不采用 LLM 直接检测原始事件

不让 LLM 扫描全部 CSV 或逐分钟决定故障，原因是：

- 输入规模远超上下文窗口；
- 数值边界判断不稳定且难以复现；
- 推理成本高；
- 容易受无关日志和高频噪声影响；
- 无法稳定保证时间区间和枚举输出格式。

### 9.2 LLM 接入位置

LLM 只处理模型压缩后的结构化事件摘要：

```text
事件边界
Top-N 候选及分数分解
故障前/中/后关键变化
局部拓扑与业务方向
支持证据和反证
本地分类 Top3
```

LLM 可完成：

- 对灰区事件给出“支持/不确定/反对”意见；
- 识别两个候选事件是否可能是同一根因的重复症状；
- 对根因 Top5 进行有限幅度重排；
- 在官方分类闭集中复核大类和子类；
- 生成可审计的证据解释。

LLM 不能：

- 创建模型完全没有提出的新时间段；
- 单独删除高置信事件；
- 输出枚举外网元或类别；
- 根据事件数量逼近 292；
- 读取 ground truth 或 Case 专属答案。

所有 LLM 响应必须为结构化 JSON，并通过 schema、枚举、证据 ID 和置信度范围校验。失败时回退到本地模型结果。

首版接口仅对本地置信较低的事件调用，并且只接受本地 Top5 的排列与官方合法类别对；“不确定”或低于 0.65 置信门槛的建议只记入审计日志、不覆盖本地结果。LLM 不能修改事件时间、创建、删除或合并事件。

## 10. 训练和推理流程

### 10.1 训练

```text
build_features
  ↓
fit_scalers
  ↓
self_supervised_pretrain（第一轮）
  ↓
排除最高异常分位窗口
  ↓
self_supervised_finetune（第二轮）
  ↓
synthetic_fault_training
  ↓
calibrate_scores
  ↓
保存 checkpoint + scaler + registry + manifest
```

训练产物必须记录随机种子、配置哈希、数据清单、Git commit、模型权重哈希和运行环境。

### 10.2 推理

```text
load feature store
  ↓ 滑窗推理，重叠区平均
minute scores
  ↓ 全局半马尔可夫解码
event proposals
  ↓ 因果子图
root Top5 + category
  ↓ 可选 LLM 复核
validated predictions.jsonl
```

四张 5090 用于模型训练和批量窗口推理。CSV 解析主要受 CPU 与磁盘限制，应按文件并行，不应期待 GPU 加速读取阶段。

## 12. 与数据侧的接口

模型侧需要数据侧最终提供以下机器可读信息：

1. 每个字段的单位、Gauge/Counter/State 类型和合法范围；
2. 同一分钟多行记录的正确聚合方式；
3. Counter 复位、缺失、过期和采集失败的定义；
4. traffic 的源端、目标端、`target_domain`、`flow_type` 语义；
5. `target_domain` 到目标服务组或精确服务实例的可靠映射；
6. NetFlow 的方向、观测路由器、接口和端点含义；
7. routing label 和 FRR hostname 到官方网元的映射；
8. 日志模板、严重度和状态恢复事件的归一化结果；
9. 可确认的周期性业务模式和数据采集中断区间；
10. 第二批数据相对第一批的字段增删和语义变化。

数据侧不需要人工标注正式测试集故障。其交付物是字段语义、质量规则、实体映射和可复现的数据统计，这些内容决定张量是否正确，不直接替模型生成答案。

## 13. 验收标准

### 13.1 数据层

- 七类数据都有非零覆盖统计或明确的合法空源说明；
- 原始行数、有效行数、坏行数和聚合后分钟数可追溯；
- 同一配置重复构建得到相同索引和特征；
- 缺失值、Counter 复位和时间对齐有单元测试；
- 全量特征构建不依赖一次性加载全部 CSV。

### 13.2 检测层

- 事件全局互不重叠；
- 每个事件持续 1～30 分钟；
- 不因源城市不同重复报告同一目标故障；
- 事件有模型概率、变化点、多源一致性和恢复证据日志；
- 事件数只做诊断，不以 292 为硬目标。

### 13.3 定位和分类层

- Top5 来自官方枚举、顺序稳定且无重复；
- 只有观察者证据时，`traffic-vm` 不应默认成为 Top1；
- 目标侧候选不会因没有源城市本机证据而被过滤；
- 分类始终来自官方 taxonomy；
- 每个根因和类别都能追溯到支持证据与反证。

### 13.4 回归与泛化

- 三个公开样例保持正确匹配、根因和分类；
- 合成 1、5、15、30 分钟故障均可被检测；
- 对业务周期、单分钟稀疏 ratio、采集缺失和恢复尾部进行负例测试；
- 全量运行执行消融：无 traffic、无日志、无图融合、无 LLM；
- 输出通过官方 evaluator 和 schema 校验。

## 14. 主要风险与控制

| 风险 | 控制方式 |
|---|---|
| 无训练标签 | 自监督正常建模、合成扰动、公开样例仅作回归 |
| 故障污染自监督训练 | 稳健缩放、两轮训练、剔除最高异常分位 |
| 张量过大 | 分钟聚合、稀疏边、内存映射、滑动窗口 |
| traffic 目标实例不明确 | 服务组虚拟节点、数据侧映射、禁止猜测 |
| 第二批出现新类别 | taxonomy 配置驱动、保留开放集置信度日志 |
| LLM 幻觉或格式错误 | 结构化 JSON、枚举校验、证据引用、失败回退 |
| 再次围绕样例过拟合 | 全量无标签诊断、合成压力测试、消融与稳定性指标 |

## 15. v2.0 成功判据

v2.0 的成功不定义为“事件数更接近 292”，而定义为：

1. 输入真正形成稳定、可复用的多源张量；
2. 一次真实故障在全网只形成一个事件；
3. 模型能区分观察位置、症状位置和根因位置；
4. 检测、定位和分类均有可训练模块，而不是不断叠加 Case 规则；
5. 结果可复现、可审计、可在四张 5090 上批量训练和推理；
6. 后续拿到数据侧语义成果时，只需更新特征注册表和映射，不必再次推倒模型架构。
