# v2.0 模型重构设计（2026-09-24）

## 目标和证据边界

输入仍是七类原始观测，统一为带缺失掩码的分钟张量；输出仍是官方 `predictions.jsonl`：事件起止、合法网元 Top-5、故障大/小类。公开样例仅用于回归验收，不能作为训练标签或正式数据阈值的来源。第一批全量数据无真值，不按官方公布的故障总数截断预测。

| 阶段 | 输入/输出格式与形状 |
|---|---|
| 原始输入 | 七源 CSV；`processed` 样例或 `*_data` 正式目录 |
| 特征存储 | `node_values/node_mask [T,N,F_n]`、`edge_values/edge_mask [T,E,F_e]`、`log_values/log_mask [T,N,F_l]`，`T` 为分钟，`N` 为官方网元，`E` 为观测关系 |
| 检测输出 | 本机故障族证据 `[T,N,C]`、本机概率 `[T,N]`、业务症状 `[T,E]`、全网概率 `[T]` |
| 解码输出 | `K` 个不重叠的 1～30 分钟事件；每事件的根因分数 `[N]` 和候选条件类别分数 `[N,C_taxonomy]` |
| 提交 | UTF-8 JSONL，每行一个 `prediction_id`、起止 UTC、`root_cause_top5`、`fault_category`；详细分项另写 `inference.json` |

当前 v2.0 公开样例只有 1 TP、3 FP、2 FN（10.76 分），而 v1.6 三例为 96.01 分。根因在检测前端：60 个有效观测分钟里 33 分钟落在三个已知故障内，低能量 60% 校准段仍被故障污染；全网家族分数还把具体网元的直接异常与大量症状平均。解码器边界修正后结果不变，说明仅调解码阈值没有意义。数据侧报告指出 CPU、可用内存、磁盘饱和应是根因本机证据；traffic、NetFlow、scrape 多为症状或观测质量。该报告只有三个样例的归因解释，不作为隐藏标签或固定答案。

## 主链路

```text
七源 CSV → 规范化观测 → [T,N,F_node]/[T,E,F_edge]/[T,N,F_log] + 同形 mask
    → 分源语义与量程契约 → 本机直接证据张量 [T,N,C] / 症状张量
    → 全时段稳健参考 + 状态转移 + 持续性 → 网元级事件概率 [T,N]
    → 全网事件概率 [T] → 1~30 分钟全局非重叠解码
    → 候选根因直接性/先后/传播排序 → 候选条件分类
    → 可选服务器 LLM 受约束复核 → 官方 JSONL + 可审计推理日志
```

`C` 是语义故障族数，不将所有 CSV 列当作等价异常信号。主机资源、接口错误和明确的路由状态可独立提供直接证据；流量体积、NetFlow、scrape 不单独把观察节点判为根因。经请求量收缩的 traffic 质量异常可以独立提出服务事件候选，但具体服务实例仍须由定位层寻找。未知、缺失与正常零值严格区分。事件概率不依赖单个全网校准分位点，因此短样例也能工作。旧神经 TCN 的重构/预测残差保留为独立对照通道；只有全量对照证明提升时才考虑融合。

## 数值规则与泛化保护

逐 `(网元, 指标)` 用观测 mask 估计全时段稳健参考，并用指标量纲下限约束 MAD；这避免 30 分钟故障把短滚动中位数翻转。当前对普通 gauge 单点尖峰降权，对状态转移允许单分钟触发；局部多尺度参考仍需八城审计后验证。服务失败率使用同边求和后的失败速率/请求速率并做伪计数收缩，不把最大单序列比例乘总请求量；采集失败被隔离为观测质量信号，而非直接根因。量程信息用于相对异常之外的独立证据，不允许磁盘利用率 10% 与 100% 因相对倍数相同而等价。

在每个网元/故障族上聚合直接指标，得到时间曲线；全网事件概率取最强本机概率与经持续性约束的服务质量概率，而非全网均值。定位仍使用事件内的直接强度、先后、恢复与业务关系；分类读取多个候选的本机字段，不能硬绑定 Top-1 城市。LLM 不创建、删除或移动事件，只可在已有候选与官方 taxonomy 内给出受约束的根因/类别复核。原始七源数据量大，逐点用 LLM 检测成本和边界可复现性都不理想，因此它不是第一层事件检测器。

## 目录与兼容性

`aiops_v2/data/` 继续负责原始数据投影与特征存储，其中正式 `*_data` 与样例 `processed` 都可发现；NetFlow 先在临时 SQLite 上聚合，再逐条流出，不在内存中持有整城结果。`aiops_v2/detection/` 是可审计直接证据主检测器，`events/`、`localization/`、`classification/` 负责后续决策，分类读取只触及事件前 30 分钟和事件窗口。`models/llm_review.py` 保留服务器兼容接口。旧 TCN/训练模块暂留作可复现实验对照，但不再作为默认事件门控。`baseline/` 是 v1.x 对照，`sample/` 与 `AIOps_data_dyx/` 属于外部原始材料，不删除。清理仅针对确认无引用、无用户结果依赖的项目生成物；不重写 Git 历史。

## 验收

1. 契约测试：七源行数守恒、mask、合法 Top-5、类别、1~30 分钟、无并发。
2. 合成行为：1/30 分钟、CPU/内存/磁盘、路由/接口/服务、观测中断、稀疏 ratio、跨城症状；不使用样例答案训练。
3. 公开样例只作回归：与 v1.6 同口径比较 AD、RCA、Major、Minor、TP/FP/FN；当前从原始 CSV 重新构建后为 96.01、3 TP/0 FP/0 FN，说明防回退达标，但不证明全量泛化。公开样例已经用于调试，不能视为独立测试集。
4. 八城全量：先检查源覆盖和审计、时间/城市/类别分布及运行资源，再由服务器运行；没有隐藏标签时不得宣称真实准确率。

成都单城首轮审计读取七源文件并输出 170 个候选事件；其中 123 个以服务质量症状为主。单城探针观测远端目标服务，因此它不等价于“成都发生 170 个故障”，也不能用单城根因 Top-1 推断跨城定位准确率。八城合并后必须重点核查这类症状事件是否与远端直接证据对齐，以及不同探针的同一故障是否被全局解码为一个事件。
