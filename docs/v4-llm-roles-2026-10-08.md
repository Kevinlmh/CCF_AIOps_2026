# v4 多角色诊断与官方导出交付记录

本轮对应原计划剩余四批中的前三批，累计由四批推进到七批。实现继续遵循“统计特征和轻量聚类发现运行状态，规则补充线索，同一个 LLM 通过不同角色确认事件、定位根因、分类，再一致性复核”的设计。代码没有沿用 v1–v3 诊断阈值、提示词、排序或合并规则。

| 原设计要求 | 本轮实现 | 结论边界 |
|---|---|---|
| 一个 LLM、多角色 system prompt | `backend.py`、`prompts.py`、`engine.py` | 同一配置模型，不同独立会话；HTTP 和 replay 明确区分 |
| 统计/聚类/规则先产生证据 | 只读 contract 2 索引及 `tools.py` | 聚类/稀有状态不当作故障标签，参考不是已知健康 |
| 事件确认与拆分 | `contracts.py` 的候选窗口守恒 | bundle 可拆多事件；首版同窗口恰好分配一次，物理边界未知 |
| 支持、反证、缺失和原始记录 | 完整交付事实的引用注册、分块工具 | 未取回原文不能 raw 引用；缺测不能判正常 |
| 定位与分类相互独立 | `diagnosis.py` | 相同事件/包输入，不传递对方结论；复核才汇总 |
| 根因/分类需合法且有事实支撑 | 80 网元、32 配对、设备自身/事件支持校验 | 程序保证引用与格式，不能证明自然语言因果正确 |
| 一致性复核 | 独立 review + 前后确定性校验 | 不能修复非法 ID/引用或改写边界；矛盾/不足保留待判断 |
| 官方导出 | `export.py`、官方 `validate_prediction` | 最多五个排序候选、不补齐，恰好五字段；不调用提交脚本 |
| 可运行与可审计 | `pipeline.py`、CLI、summary-last、SHA256 | 本轮是证据索引到导出入口；全原始数据实验闭环在第四批 |

## 实际验证

基线 170 项测试通过。新增测试采用先失败再实现；包含真实本地 HTTP 服务、实际 CSV→窗口→状态→证据→角色→JSONL 的集成，以及非法类别/引用、角色失败、预算、覆盖守恒、独立会话、输出保护等行为。最终测试数和审查结果记录在同目录进度记录中。

公开样例已对 contract 2 的一个 bundle 运行四角色 replay：`beida-br-1`，4 个候选窗口，4 次回放调用；当前索引共 695 个 bundle，仅选 1 个，其余 694 个明确未选。复核结果为 deferred，官方预测文件为空。人工配置的模拟结论仅测试协议，不能用于真实准确率或提交。原始样例扫描范围为 604284 行、71208 个状态，参考区间仍标 `known_healthy=false`，无时区语义仍未官方确认。

本地结果目录：`outputs/v4/llm-roles/20261008/public-replay-simulated/`；fixture 和选择清单位于其父目录。输入索引 SHA256：`0f71c3cf302d22f0fe4d7ab8b7d851a29dd81fded57b6a0e901d08e317b21faf`，运行前后相同，产物哈希核对通过。531 个既有受保护文件（含两批数据、已有 output/outputs 和 submit.py）大小、mtime、inode 均不变。

本轮未读取 `submit.py`、密钥文件、未调用真实远程模型，也未处理全量第一/第二批原始数据。真实 HTTP 适配器已有本地协议测试，实际供应商与模型的工具能力和诊断质量仍需实验验证。接口来源是已读取的 [OpenAI Docs：Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 和 [Function calling](https://developers.openai.com/api/docs/guides/function-calling)；竞赛字段由保留的官方 schema 校验。

## 剩余一批及下一步

1. 打通原始 CSV→统计/窗口→状态→证据→真实角色→导出的一体化任务与配置；先用公开样例和明确的小范围验证模型协议、费用、错误分布，再扩大。
2. 做公开样例评测、分批统计/参考覆盖检查，补官方知识卡与规则/提示词依据，检查第一批全量和第二批全量的差异。
3. 做规则/统计/聚类/不同角色/复核的消融与错误分析，记录模型、提示词、配置、输入版本、调用耗时与费用。
4. 完成实验台账和容器复现，依据结果校准参考、事件边界、拒答策略及预算。没有真实模型结果前不宣称多智能体已改善得分。
