# 多源混合诊断模型 v1.1 设计

## 目标

在不读取正式答案的前提下，完整扫描第一批八城市、七来源、约 96 GiB 的正式数据，以受控内存完成事件检测、根因 Top5 和 28 类闭集故障分类；保留本地规则推理、本地 Transformers 和 OpenAI-compatible API 三种决策后端。

## 约束

- 正式数据位于 `*_data/`，公开样例位于 `processed/`，两种结构必须兼容。
- 原始数据不可改写，推理过程不得读取 ground truth。
- 正常观测可以在完成统计检测后释放；任何文件、行或字段过滤都必须可审计。
- NetFlow 可聚合但不得静默丢弃乱序行；原始五元组不得进入 LLM 请求或诊断日志。
- 默认本地模式不得依赖 Torch；服务器推理接口必须保持可选。

## 架构

### 输入与审计层

`preprocessing/multisource.py` 负责统一发现 `processed/` 与 `*_data/` 中的七类官方 CSV，执行表头校验、节点归一化、空值处理和逐源行数守恒统计。正式八城市根目录启用严格清单校验，缺源、重复源和错误表头不会静默通过；只有表头的数据源会作为零行来源进入审计（FRR 无日志时允许出现这种情况）。

### 流式特征层

新增 `preprocessing/streaming.py`。普通指标逐行转换；Counter 根据真实分钟间隔计算增量并处理重置；State 使用正常状态进行定向检测。每条序列只保留最近 60 个有效点。

NetFlow 使用磁盘 SQLite 做精确的乱序聚合，聚合结果按分钟、节点、接口和协议流入检测器。这样会完整扫描原始行，但不会在内存中保留 4.66 亿条五元组。

### 在线异常层

`anomaly_detector/streaming_detector.py` 按滚动中位数和 MAD 在线评分。正常点评分后释放；异常证据按分钟、来源、节点保留最强若干条，防止噪声导致内存失控。短序列和长序列维持现有 warm-up 语义。

### 事件与 RCA 层

先按分钟能量得到候选窗口，再按城市和跨城业务关系拆分互不相关的并发故障。根因排名继续融合强度、持续性、先后顺序、多源支持、直接性与拓扑解释，并保留恢复尾部裁剪和纯症状惩罚。数据质量当前写入推理审计；待数据侧确认缺失语义后，再决定是否进入候选分数，避免把“无业务流量”误罚为“采集缺失”。

### 分类与 LLM 层

本地分类为 28 类原型增加支持/冲突信号。进入 LLM 前，确定性模型把 80 个合法候选压缩为有证据、关键上游和城市代表组成的有界集合。

接口保留：

- `local`：纯本地统计、拓扑和原型模型；
- `transformers`：服务器本地权重；
- `api`：OpenAI-compatible `/chat/completions`，可对接 vLLM。

API 后端支持超时、重试和环境变量密钥；正式输出按事件顺序确定性落盘。

## 错误处理与可审计性

推理日志记录文件清单、每源读取/有效/无效/过滤/发射数、时间范围、未知节点、警告、异常数和事件证据。Schema 不兼容、正式清单缺失和输出非法时失败退出。原始地址、端口和 API 密钥不写日志。

## 测试

- 单元测试：双目录发现、清单校验、空值、Counter、State、流式 warm-up、证据限流、LLM 候选压缩。
- 集成测试：三公开样例、正式目录形状、七源覆盖、输出 Schema、禁止读取 ground truth。
- 性能测试：抽样解析速率、峰值状态数量、NetFlow 临时磁盘估算。

## 不在本轮自动决定的参数

数据侧仍需确认单位、Counter/Gauge/State 分类、正常分布、日志模板和 Case 证据链。这些结论通过配置调整，不阻塞本轮工程实现，也不硬编码未经验证的业务假设。
