# v4 混合诊断架构与数据基础范围

用户已选择并授权实施：统计特征与轻量聚类发现运行状态，规则补充异常线索，同一个 LLM 通过多个角色完成事件确认、根因定位和故障分类。采用里程碑推进，本次交付第一个里程碑，不把尚未实现的聚类或 Agent 标为完成。

## 总体架构

原始数据 → 统计与质量检查 → 标准化观测 → 多视角窗口特征 → 聚类、统计变化、领域规则 → 候选事件 → 事件确认 Agent → 独立的定位与分类 Agent → 一致性复核 → 官方 JSONL。

- 聚类学习运行状态，不将簇号视为故障标签；不固定只有正常/故障两个簇。
- 设备、接口、路由 peer、业务目标保留不同粒度；缺测不等于正常或真实零值。
- 一个固定 LLM 后端承担独立角色，程序调度；先实现三个核心角色，再按实验结果增加状态解释与复核。
- 支持证据、反证和缺失证据进入提示词；所有结论可追溯原始记录。
- 每批独立统计和学习，共享通用代码、官方拓扑、类别和公开知识。
- 事件起止来自观测变化，不预设故障数量、最长时长或间隔。

## 本次：数据基础

使用 Python 3.10+ 标准库实现，避免在数据层引入 GPU、LLM 或聚类依赖。

### 发现与原始记录

自动发现七类 CSV，兼容公开样例、第一阶段和第二阶段的嵌套目录。所有识别出的文件均列入清单，不静默选择 processed 文件或隐去重叠输入。调用者应使用单一原始数据目录。

逐行流式读取，保留原始字段、完整日志、地址与端口。CSV 行起止位置考虑多行引号字段。空文件和仅表头文件有效；重复表头或不可读取的 CSV 明确报错。

标准化记录包含 batch、record_id、source、source_file、record_index、line_start/end、UTC timestamp、city、node_id、dimensions、values、text、raw、quality_flags。ID 由批次、相对路径、记录位置和原始内容确定；缺少时间、网元不明或坏数值的行也保留。

无时区时间按 UTC 处理并打标；完整原始时间仍保留。只接受合法完整网元或有边界的合法角色名，不能把 br-10 映射为 br-1。traffic 的源角色 traffic-vm 来自官方业务数据语义，记录映射来源，不推断目标 service 实例或实际传播路径。

本层不差分累计计数器，不计算 NetFlow 聚合，不截断日志，不裁剪数值，不赋予故障类别或异常方向。

### 统计

输出文件清单、来源覆盖、表头问题、字段缺失/零值/非数值/非有限值、数值范围/均值/标准差/分位数、时间范围、实体与维度覆盖、重复/乱序线索。

均值、方差、范围、计数采用全扫描值。分位数和 MAD 用固定种子、有上限的蓄水池样本估计，报告容量与实际样本数。字符串基数、实体/时间序列跟踪及近邻重复检查均有上限，超限明确报告；不将局部重复检查说成全局精确去重。

可指定每文件前 N 行做快速检查，报告标为 prefix sample，逐文件记录是否完整，不能解释为全量分布。没有识别到文件时返回错误，不能生成正常结论。source manifest 记录相对路径、文件大小、mtime、表头及已解析记录内容摘要；摘要不是原文件字节哈希。

统计不填补缺失值，不做跨批次比较或利用历史标签。字段词典区分身份字段、指标字段和文本字段；单位/指标类型仅作已知线索，未经核验的语义留空。routing 的不同 metric_name 分开统计，不混合 long-table value。

### 证据存储与查询

可选 SQLite 存储，写入批次元数据、文件清单和完整标准化记录。每次建立新数据库，拒绝覆盖已有文件；使用临时文件和事务，失败不发布部分数据库。

只读查询必须明确 batch，支持 source、node_id、时间范围、record_id、limit；查询保留原始字段和质量标记。时间过滤按统一 UTC 微秒格式比较，start 包含、end 不包含；查询时间必须带时区。

CLI 提供 profile、ingest、query 三个子命令；报告目录拒绝覆盖已有报告，输入和输出目录隔离。完整诊断与官方结果提交尚不在本次范围。
