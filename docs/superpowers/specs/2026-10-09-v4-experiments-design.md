# v4 最后一批：一体化运行与实验设计

依据：最初 `2026-10-08-v4-design.md`、已完成七批代码及用户/师兄的混合架构要求。用户已明确授权完成最后一批并审查整个项目；在现有 v4 直接执行，不重开设计确认。

## 必须实现

默认链路仍为原始统计 → 多视图窗口 → 无监督运行状态/统计/规则线索 → 证据包 → 同一模型事件确认 → 相互独立的定位/分类 → 复核 → 五字段官方 JSONL。轻量聚类不变成监督标签；不同批次不共用学习结果。已有数据、输出、submit.py、v3 存档保持原样。

最后一批增加：严格 JSON 配置的一体化 CLI；通用故障知识卡和可选运行状态解释角色；独立角色/联合角色、LLM复核/程序校验、知识卡开关、统计/聚类/规则组合的实验消融；独立于推理的公开真值评测、逐条错误分析和消融比较；配置、代码、提示、输入输出摘要、模型、调用/耗时/token/明确报价的实验记录；Docker 运行材料。

## 配置与隔离

`load_config(path)` 只允许 schema_version、batch、raw_root、naive_timezone、profile、features、states、evidence、agents、backend、pricing。所有未知键、类型、无穷数和非法范围均预检拒绝；相对路径按配置文件目录解析。配置不接受真值、答案或明文密钥，HTTP 密钥只读取指定环境变量。所有新产物写入不存在的新运行目录，禁止位于原始输入、项目 data 中。推理不读取评测标签；评价命令在已封存的运行上另写新目录，验证摘要和 batch 后才读取真值。

运行根目录采用固定最终路径，避免移动目录造成证据数据库的原始文件路径失效。summary.json 最后发布，是成功完成标记。中途失败保留已完成阶段和不含异常原文的 failure.json；不伪装为成功。prefix_sample 和选择部分 bundle 均标明 partial；没有真值时不报告准确率；未完成模型判断不视为健康。

## 角色扩展

通用知识来自官方公开类别及规则 FAQ，注明来源/用途；故障机理核验建议是通用工程假设而非官方测试答案。默认启用知识卡，适用于所有四角色。可选 state_explanation 只解释已观测运行状态和限制，不能把簇命名为故障/健康标签；解释失败不绕过事件确认。

联合定位/分类和关闭 LLM 复核仅用于明确的实验模式。联合角色只有一条真实 joint_diagnosis trace，绝不伪造两条独立角色运行。程序校验模式没有 review trace，明确声明缺少语义复核；其导出单独验证实际角色、事件、引用、官方字段，并禁止由默认严格 export 接受。纯线索 discovery_only 不产生可提交预测、不计算模型准确率。

## 可比实验和评测

`ablate` 每个变体完整独立运行，不共享可变模型/诊断缓存；重复预处理的运行时间单独记录，成本透明。变体为 full、statistics_only、cluster_only、no_rules、joint_roles、program_review、no_knowledge、with_state_explanation、discovery_only；所有 backend 共用模型配置，回放可按变体独立提供文件。

真实 HTTP 运行才可能用于模型效果评估；Replay 永远 simulated，分数仅为流程契约验证。样本/部分选择需评价者显式 allow_partial，记录不可当全量成绩。错误分析保留 FN/FP、匹配 Dice、时间偏差、根因名次、类别错误；官方评测实现复用不重新编写。不裁掉真值来抬高得分。

每次实验记录 UTC 时间、batch、规范化配置 SHA、代码/公共配置/所有角色提示和知识卡 SHA、Python/平台/git 状态、输入和各阶段产物摘要、所有角色/失败次数、实际 usage 覆盖率。报价由用户配置 USD 每百万输入/输出 token；缺报价或不完整 token 时成本为 null，已知部分单列；模拟 token 不是账单。没有随机种子的程序不虚构种子，聚类现有确定性算法保持不变。

## 复现和验证

纯标准库 runtime，Python >=3.10。Docker runtime 不复制 data/outputs/submit.py/.env/归档，原始数据只读挂载；输出挂载独立新目录。公开来源和在线 API 的依赖说明写入文档，不声称官方审核环境已保证联网。用真实小原始数据、回放、异常中断/摘要篡改和 CLI 子进程验证，再尝试实际 Docker build/run；服务不可用时报告具体限制，不能只凭 Dockerfile 声称容器成功。

最后独立审查全部 aiops_v4、共享官方 schema/evaluator 和原始设计，处理 Critical/Important；逐项给出架构符合度及实测边界。代码完成不等于已证明比赛效果：真实模型与全量两批实验仍由实际配置和运行验证。
