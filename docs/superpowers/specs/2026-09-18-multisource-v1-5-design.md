# 多源混合模型 v1.5 设计

## 目标

v1.5 面向 v1.4 八城全量运行暴露出的系统性问题，不以三个公开样例为调参目标。公开样例仅用于防止召回、定位和分类能力回退。

核心原则：事件必须由可解释、相互独立且具备城市边界的证据开启；支持证据只能补强，不能通过重复表达或跨城汇聚制造事件。

## v1.4 暴露的问题

1. 事件能量按全局分钟聚合，同一时刻不同城市的异常会互相增强，之后再拆分无法完全消除跨城粘连。
2. `error_rate`、`error_ratio`、`success_ratio` 等同一业务结果的不同表达会重复贡献能量。
3. 大量 CPU 事件具有很高的相对偏离，但绝对使用率很低；统一的三分钟持续规则没有体现指标语义。
4. 周期性为零的磁盘读写速率会作为支持证据进入事件，扩大证据规模并干扰定位。
5. 防火墙设备被定位为根因时，CPU 故障仍可能被分到通用资源类别。
6. 当前缓存校验会正确拒绝旧版本缓存，但缺少只重放证据分段的安全工具，导致每轮算法验证都必须重新扫描五亿行原始数据。
7. 公开样例 AD 边界有所收缩，但不能通过为样例补固定时间的方式修复；边界恢复必须由根因设备附近的真实证据驱动。

## 设计

### 1. 城市内生事件分段

在计算分钟能量前，根据节点前缀和网络配置把证据分到城市。每座城市独立完成触发资格判断、分钟能量计算和事件窗口生成。无法归属城市的证据不得单独开启城市事件，只能作为受控上下文。

这使城市边界成为检测前提，而不是事件生成后的补丁。已有的并发事件拆分仍保留为防御性处理。

v1.5 默认不自动合并不同城市事件。跨城关联交给候选排序和后续 LLM 推理表达，避免仅凭时间重叠把多个独立故障合成一个事件。后续若数据侧确认了可靠的跨城链路语义，再增加显式、可审计的合并规则。

### 2. 触发族去重

分钟能量从“按来源选前三个点”改为：

1. 同一分钟、同一来源、同一触发族只保留最高分；
2. 再对不同触发族做来源内融合；
3. 最后做跨来源融合。

业务成功率、错误率和错误比例属于同一 `service_outcome` 族；CPU 与 load 属于同一 `cpu_pressure` 族。这样保留独立信号，同时消除同一事实的重复记账。

### 3. 指标语义化持续规则

为 CPU 使用率引入可配置的绝对值分层：

- 低于 20%：不能凭自身相对偏离开启事件，只有同节点独立来源或独立触发族证实时才可参与；
- 20%–35%：需要至少 5 个有效异常分钟；
- 35% 及以上：需要至少 3 个有效异常分钟。

“有效异常分钟”仍要求该分钟触发能量达到保留阈值，不再把相邻任意弱点当成持续。规则写入配置，并保留默认通用规则，便于数据审计后调整。

### 4. 支持证据净化

对于磁盘读写速率等天然稀疏指标，零值不作为异常支持证据。只抑制配置中明确声明的 `support` 指标零值，不影响磁盘利用率、IO 等待、非零突发或状态型指标。

### 5. 分类与设备角色一致性

候选根因为防火墙设备，且主要信号为 CPU 压力时，分类必须映射到 `firewall/cpu_pressure`。该约束在本地分类器输出层执行，并记录原因；不把所有防火墙异常一律改成 CPU 故障。

### 6. 边界恢复

仅在事件已经通过资格判断后，允许使用同一根因设备、同一触发族的相邻真实证据恢复最多一个配置窗口的边界。不得用固定样例时间、全局弱证据或无证据填充边界。若当前事件对象没有足够上下文，v1.5 宁可保持保守边界，也不制造时间段。

### 7. 离线证据重放

新增独立的离线重分段入口：读取既有证据缓存、使用当前配置重新生成事件和审计摘要，但不把结果伪装成当前版本生产缓存。原有指纹校验保持不变。

## 验收标准

- 全部单元与集成测试通过；新增规则必须有先失败后通过的测试。
- 三个公开样例保持 3 个 TP、0 FP、0 FN，根因与分类不回退。
- 全量证据重放中：支持证据独立开启事件为 0；同族重复计分被消除；跨八城直接证据事件显著下降；低绝对值 CPU 驱动事件和磁盘零值支持污染显著下降。
- 不以事件总数接近公开先验为验收条件，不使用人工标签或目标数量截断。
