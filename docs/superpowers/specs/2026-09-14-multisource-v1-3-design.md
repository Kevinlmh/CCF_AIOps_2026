# 多源混合诊断模型 v1.3 设计

## 1. 目标

v1.3 在不改变官方输入和提交 JSONL 协议的前提下，修复 v1.2 的证据语义、事件准入、长故障基线污染、根因排序和缓存可审计性问题。模型继续采用“七源数据预处理 → 异常证据 → 事件切分 → 根因 Top5 → 闭集分类/可选 LLM 复核”的混合架构。

本轮优化以正确性和可解释性为第一目标，不以把成都事件数机械压到某个预设值为目标。公开规则允许短故障，因此禁止使用固定 3 分钟或 5 分钟时长过滤器。

## 2. 已确认根因

1. `traffic.*.*throughput*` 在指标语义配置中重复出现，首条触发规则遮蔽了后续辅助证据规则。
2. 流式证据桶只按分数截断，高分 `support` 可以挤掉较低分但决定事件召回的 `trigger`。
3. 单分钟存在状态/FRR 证据时，当前实现会放行该分钟全部触发点，扩大了无关尖峰的影响范围。
4. `MetricRule.normal_value` 被读取但未进入数值证据生成，已知正常值的状态指标仍依赖滚动历史。
5. 事件准入中的同分钟“不同族”定义过宽，CPU 与 load 等强相关派生指标可能被当作相互独立证据；同时，持续性只判断相邻异常点存在，没有显式累计有效异常分钟。
6. 滚动中位数持续吸收故障值。60 点历史在故障第 31 个点附近翻转；短历史序列更早翻转，造成长故障截断和恢复尾部幻影。
7. RCA 的严重度、持续度和来源多样性没有区分 `trigger` 与 `support`，会放大吞吐、NetFlow 等症状型证据。
8. 城市候选硬过滤缺少作用域日志，也没有利用显式跨城拓扑边扩展候选。
9. 内存模式没有经过与流式模式相同的指标语义转换；事件缓存指纹也没有覆盖检测实现代码。
10. 推理日志缺少总分钟数、比例和候选裁剪信息；事件缓存之前没有可复用的“切分前证据”层。
11. 回归审计进一步发现，`observed_qps` 属于工作量而非质量信号，load average 会在资源恢复后滞后衰减；两者作为 trigger 会错误延长事件。
12. 同分钟跨节点佐证原先按整分钟生效，无拓扑关系的两个尖峰也会互相“背书”；分类器还会重复累计同分钟的 CPU/load 等相关信号。

## 3. 方案选择

采用保守增强方案：保留鲁棒 MAD 打分作为偏离信号，新增语义量程位置作为独立证据维度；检测到异常后，在有限时长内冻结该序列的基线，避免故障值污染参考窗口；事件准入同时使用即时状态、自身持续、跨来源/跨因果族佐证和极端语义位置。

不采用以下两种方案：

- 固定最短故障时长：虽然能快速减少成都短事件，但会直接损失规则允许的 1 分钟故障。
- 本轮直接全面替换为 CUSUM/二元分割：变化点模型有价值，但现有公开标注不足以确定漂移、缺失和周期负载下的阈值，改动风险高于当前收益。v1.3 先用有限冻结基线解决已复现的 30 分钟污染问题，并保留以后替换打分器的接口。

## 4. 指标语义与证据结构

`MetricSemantics` 加载时执行配置校验：模式字符串不得重复，`kind`、`direction`、`event_role` 必须属于允许集合。吞吐量、工作量 QPS 和 load average 统一为 `support`。

`NumericObservation` 增加可选 `normal_value`。已知正常值的 state 指标不需要历史预热：等于正常值不产生证据，偏离正常值立即产生 `direction=state` 的触发证据；Counter reset 使用正常值 0，复用相同路径。

`AnomalyEvidence` 增加 `[0,1]` 的 `semantic_score`。该分数表达原始值在公开指标物理量程中的危险位置，不替代鲁棒分数：

- 高危险指标使用 `high_start` 到 `high_full` 的线性位置；
- 低危险指标使用 `low_start` 到 `low_full` 的线性位置；
- 没有可靠量程的指标保持 0，不凭经验硬造阈值；
- 语义分数参与事件准入、NMS 质量、RCA 和 LLM 上下文，但普通中等量程异常仍可凭持续性进入事件。

## 5. 长故障基线与事件准入

每个数值序列维护正常历史和连续异常计数。超过证据阈值的观测在 `baseline_freeze_anomaly_points` 个点内不写入正常历史；超过冻结上限后才允许参考窗口逐步适应长期新稳态。离线和流式检测使用相同规则。

事件准入按证据点判断：

1. state/FRR 仅立即放行自身，不放行同分钟其他 gauge；
2. 同一序列在配置窗口内达到最少有效异常分钟数时放行该序列；
3. 同分钟存在配置要求数量的独立因果族，且至少满足跨来源或跨节点条件时，放行参与佐证的点；
4. 达到极端语义位置阈值的点允许形成 1 分钟事件；
5. CPU/load、磁盘吞吐派生项、同一服务的成功率/错误率等相关指标折叠为一个因果族。

跨节点佐证必须有 `related_node_ids` 显式关系；同节点跨来源证据仍可互相佐证。不能因同一分钟另一个无关节点恰好出现尖峰，就放行当前证据。

该规则保留短状态故障和极端资源饱和，同时抑制单源、单分钟、相关派生指标共同波动造成的假事件。

## 6. 根因排序与候选作用域

RCA 对 trigger 采用权重 1，对 support 使用 `support_evidence_weight`。严重度、持续度、来源多样性、直接性和拓扑解释统一遵守该权重，并在候选日志中分别记录 trigger/support 数量。

候选城市首先来自直接证据和 `related_node_ids`。如果公开拓扑中存在从已激活节点指向其他城市的显式边，则扩展到该城市；没有证据或拓扑依据的全局零分候选不进入 Top5。每个事件记录直接城市、关联城市、拓扑扩展城市、最终候选城市和被排除候选数。

NMS 质量不再依赖原始触发点数量，改为比较有效触发分钟、因果族/来源多样性、语义强度、累计能量和峰值，避免派生指标数量多的一方天然获胜。

闭集分类同样按“分钟 × 语义信号”取最大贡献，避免 CPU/load 或 disk util/read/write 的字段数量影响类别；语义量程位置作为额外加权，使磁盘接近饱和等物理强信号优先于普通相关波动。输出时间使用 Top1 根因节点的主要连续触发段，并保留可配置起止缓冲，最终严格限制在官方 30 分钟上限内。

## 7. 一致性、缓存和日志

内存与流式模式都必须先通过同一个 `MetricSemantics` 转换器。流式检测器为每个序列有界缓存前 `long_series_threshold` 个观测，确定最终属于长序列还是短序列后再按对应预热长度回放，避免早期阶跃改变冻结基线。两条路径对同一受控数据的事件边界、指标角色和状态证据保持一致。

事件缓存指纹覆盖模型 JSON、指标语义 JSON以及影响检测结果的 Python 实现文件。检测逻辑变化即使忘记手工升级版本，也会拒绝旧缓存。

新增切分前证据缓存，保存有界异常证据、观测时间范围、来源覆盖和流水线指纹。它允许在不重扫 CSV 的情况下反复验证事件准入、切分和 NMS。事件缓存与证据缓存使用独立格式标识，加载时严格校验。

诊断日志增加：总分钟数、非零分钟比例、触发分钟比例、事件覆盖分钟及比例、候选作用域和裁剪数量。日志仍不保存 API Key 或原始 NetFlow 五元组。

## 8. 兼容性和验证标准

- 模型版本升级为 `1.3`，v1.2 事件缓存因版本/指纹变化而拒绝复用。
- 官方输入目录、七源字段读取和提交 JSONL Schema 不变。
- 现有 84 项测试继续通过；所有修复必须先以失败测试复现。
- 三个公开样例必须保持 3 个合法输出并重新评测，真实故障窗口和根因不得回退。
- 成都七源数据重新全量扫描，核对七源行数守恒、内存峰值、事件数、时长、触发原因、类别和根因分布；事件数只作为噪声审计指标，不作为硬编码目标。

## 9. v1.3 首轮验证结果

- 单元测试：116 项全部通过；`compileall` 和 `git diff --check` 通过。
- 公开样例：3/3 检出，Top1 根因与细分类全部正确；`Total=96.677778`，其中 AD 36.677778、RCA 40、Major 10、Minor 10。时间缓冲被限制在检测区间内，避免越过观测边界或制造相邻事件重叠。
- 成都两周七源：七源全部行数守恒，无坏行、无警告；扫描 24,512,574 条规范化观测，复审版耗时 624.37 秒，峰值常驻内存约 410 MiB，输出 167 条 Schema 合法候选事件，时长 1～30 分钟。
- 与 v1.2 成都 276 条相比减少 109 条（约 39.5%）。仍有 132 条 Top1 为 traffic-vm，服务质量指标的周期性与事件合并方式是后续主要审计方向；在没有正式标签前不继续用事件总数硬调阈值。
