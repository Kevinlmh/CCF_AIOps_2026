# v2.0 根因—类别一致性优化设计（2026-09-24）

## 目的与证据

本轮只修复直接检测后的定位和分类证据放大，不以第一批数据的预测数量或公开三个样例作为训练目标，不改变事件解码与官方输出格式。

同一八城 feature store 的审计显示：457 条事件中有 260 条报 `resource.disk_io_pressure`；其中 186 条在 Top1 无当前磁盘直接锚点，185 条在整个事件窗口内的任何设备上都没有该锚点。`semantic._deviation()` 在近零基线上把很小的磁盘利用率/读写速率变化放大至 25；分类再跨 80 个候选聚合，因此类别可由非根因设备的弱相对波动主导。另有业务边按数量累加给目标城市的全部三台 service-vm，审计实例中 `traffic_target=36.4`，乘定位权重后压过较强的设备证据。跨城峰值驱动与 Top1 不一致从 9 增至 13，不能在无真值下全部断言为错误，但上述无设备专属性的累计量不应主导定位。

## 设计

1. **磁盘类别的量程与来源。** 保留相对变化信号，但 `node.disk_io_util` 的语义证据乘以连续的物理量程因子：极低利用率趋近零，达到有意义的利用率时保留原得分；不采用一个新的硬拒绝阈值。读/写速率仍留在直接检测的弱辅助证据中，但不能单独生成磁盘类别，因为类别归一化会把唯一的弱速率信号放大为 100% 置信度。候选类别分布仍保留跨设备证据以免遮蔽定位错误，但审计需能看出 Top1 与全局证据冲突。首次复跑暴露其余问题：原聚合把任何正信号（即使极弱）先归一化成候选的完整类别投票，再给高根因权重候选大量票。根因先验项还需乘候选绝对信号强度后归一化，使弱信号不能伪装成强诊断；跨候选证据项不变。完全无语义证据时可输出合法默认类别，但内部置信度应为零。
2. **业务组定位证据防重复。** 同一目标城市的多条业务边提供“该城市业务受影响”的证据，不是多份独立的设备故障证据；`traffic_target` 按最强边聚合而非求和。同一 traffic-vm 的 `traffic_observer` 也按最强边聚合，避免边数给观测端叠加票。保留目标城市 service-vm 的非零支持、官方 Top5 和设备直接证据优先级。NetFlow/FRR 规则不在本轮重调。
3. **吞吐症状不等于限速类别。** 首次同数据复跑发现 48 条原磁盘类别转成 `link.rate_limit`；代码将接口/业务吞吐下降直接映射为限速，缺少 policer/rate-limit 直接观测。仅保留显式 `rate_limit`/`policer` 字段作为该类别语义证据；吞吐量仍可由原数据/辅助定位使用，不单独生成限速类别。不能把类别转移当成改进。
4. **回归与接受条件。** 使用可控合成输入先重现“低利用率磁盘压过 CPU/业务类别”和“多条相同业务症状翻转跨城根因”，再实现并运行全部测试。公开三样例只作退化检查。对同一八城 feature store 复跑后，逐项比较事件时间、Top1、类别、磁盘锚点、跨城冲突和解释分量；期望可证伪矛盾减少，但不把数量下降等同真实精度提升。若公开样例的真实根因/类别退化，先查根因，不用针对样例补丁。

## 边界与风险

本轮不训练神经模型、不接 LLM、不重读原始 CSV、不用隐藏标签、不改变七源张量、掩码或 1–30 分钟非重叠输出。较低利用率也可能发生真实磁盘故障，连续量程衰减只能降低无物理量程支持的过度自信，不能作为绝对否定。目标城市业务异常也可能由跨城网络故障引起，故只修正重复计数，不强制 Top1 同城。保留原八城结果；新复跑写独立目录。
