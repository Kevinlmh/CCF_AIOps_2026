# v4 LLM roles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成共享模型的多角色诊断与可审计官方 JSONL 导出。

**Architecture:** 只读证据工具向独立角色会话提供事实；程序验证覆盖、引用、设备、类别和观测边界。一次复核后，仅接受完整合法诊断；失败与模拟运行明确标记。

**Tech Stack:** Python >=3.10、stdlib urllib/sqlite3/json、pytest；无新增 runtime dependency。

**Spec:** docs/superpowers/specs/2026-10-08-v4-llm-roles-design.md

## Global Constraints

- 同一后端、同一配置模型，独立定位和分类会话；不读取 submit.py 或密钥文件。
- 默认角色预算 6 turns / 12 calls / 120000 prompt chars / 32000 response chars，manifest 2000 windows；限制代表执行预算。
- 引用必须是角色完整见到的事实，未知健康、缺失、截断和观测边界不得隐去。
- 新产物目录、当前 batch 的只读 contract 2 索引；保留所有 data/output/outputs 文件和 v3 存档。
- 官方五字段、最多五个唯一设备，不填充、不设故障数或时长先验；模拟不报告真实准确率。

## Review Focus

- 超大原文与工具 JSON 分块：不能让未完整见到的事实得到引用资格。
- 同 bundle 多原生粒度及长事件：窗口必须恰好覆盖一次，非连续区间不能混成一条预测。
- API 拒答、畸形响应、恶意日志、重定向与服务端错误：不能执行写工具或记录鉴权秘密。
- 某角色耗尽预算或出现非法输出：后续复核不能把不完整结果导出为正常预测。
- 已有/嵌套输出路径和运行选择范围：保护输入并明确部分运行，不能伪称全量完成。
