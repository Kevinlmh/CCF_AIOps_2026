# v4 Evidence Bundles Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans, sequential TDD followed by one fresh read-only whole-change reviewer. User explicitly authorized the next milestone; no repeated approval gate.

**Goal:** Relate native events and expose traceable support/context/raw evidence to later LLM roles.
**Architecture:** Validated state artifacts → indexed SQLite → same-entity overlap bundles → compact evidence plus verified raw references → read-only CLI.
**Tech Stack:** Python >=3.10 standard library / pytest.
**Spec:** docs/superpowers/specs/2026-10-08-v4-evidence-bundles-design.md

## Global Constraints

- Preserve existing data/output/outputs/submit.py, retain currentv4, no LLM/labels/old cache.
- Onebatch, read-only queries, outputs new and outside all inputs/rawroot; summary last.
- Event IDs/references cap32, support/counter/quality cap8 (config1..32), context120s configurable, direct topology relation cap8, edgesmax512.
- Bundles preserve native event boundaries; associations are not causality or confirmed faults.
- Raw table contains selected references only; complete logs retained; explicit feature timezone.

## Review Focus

- Touching/disjoint intervals and different auxiliary/real entities must not be hard merged.
- Unscorable/absent-source states cannot become normal counterevidence.
- Truncated packages must preserve all event membership and query pagination.
- Wrong batch, rawroot/symlink traversal, mutated raw record and prefix out-of-scope must fail clearly.
- Failed publication and read-only queries must not change existing files; summary links must validate actual artifact identity.
